## Как скачать материалы курса на компьютер

### Шаг 1. Установите Git (один раз)

- **macOS:** откройте Терминал и выполните команду ниже. Если Git не установлен, система предложит установить инструменты разработчика – согласитесь.

```bash
git --version
```

- **Windows:** скачайте и установите [Git for Windows](https://git-scm.com/download/win), все настройки можно оставить по умолчанию. Дальше все команды выполняйте в программе **Git Bash**.

Если `git --version` выводит номер версии (например, `git version 2.45.0`), всё готово.

### Шаг 2. Скачайте репозиторий (один раз)

1. Откройте Терминал (macOS) или Git Bash (Windows).
2. Перейдите в папку, где будут лежать материалы. Например, рабочий стол:

```bash
cd ~/Desktop
```

3. Скачайте репозиторий:

```bash
git clone https://github.com/CSS-Research-Seminar-26-27/css_research_seminar_26-27.git
```

4. Появится папка `css_research_seminar_26-27` со всеми материалами курса.

Репозиторий публичный, поэтому для скачивания не нужны ни пароль, ни SSH-ключ.

### Шаг 3. Получайте обновления 

```bash
cd ~/Desktop/css_research_seminar_26-27
git pull
```

> **Важно:** не редактируйте файлы прямо в этой папке. Если хотите поработать с ноутбуком из материалов, скопируйте его в другую папку.

Если `git pull` выдаёт ошибку про локальные изменения (`Your local changes would be overwritten`), скопируйте свои правки в другую папку и выполните:

```bash
git restore .
git pull
```

## Сдача домашних заданий

### Как это устроено

- У каждого из вас есть **личный закрытый репозиторий** `css-seminar-ваша_фамилия`. Его видите только вы и преподаватели.
- Каждое ДЗ сдаётся через **Pull Request** (запрос на слияние): вы отправляете решение, мы его проверяем и оставляем комментарии прямо на GitHub.
- Уведомления о проверке приходят на почту, привязанную к GitHub.

### Шаг 0. Получите доступ к репозиторию (один раз)

1. Отправьте ассистенту в Telegram свой **логин на GitHub** (не почту).
2. После этого вам придёт письмо с приглашением в репозиторий. Нажмите в нём **View invitation → Accept invitation**.
3. Пока приглашение не принято, репозиторий будет выдавать ошибку 404 – это нормально.

В репозитории уже есть папки `homework-1/`, `homework-2/` и т. д. **Решение каждого ДЗ кладите в папку с его номером.**

Сдать ДЗ можно двумя способами – выберите любой.

---

### Способ А. Через сайт (без терминала)

1. Откройте свой репозиторий на GitHub и зайдите в папку нужного ДЗ, например `homework-1`.
2. Нажмите **Add file → Upload files** и перетащите файлы решения.
3. Внизу страницы выберите **Create a new branch for this commit and start a pull request**. В поле с названием ветки напишите `hw-1` (номер вашего ДЗ).
4. Нажмите **Propose changes**, а на следующей странице – **Create pull request**.
5. Готово: решение отправлено на проверку.

---

### Способ Б. Через терминал

Для этого способа нужен SSH-ключ (см. раздел «Настройка SSH-ключа» ниже).

**Скачайте свой репозиторий (один раз):**

1. На странице своего репозитория нажмите **Code → SSH** и скопируйте ссылку.
2. Выполните:

```bash
cd ~/Desktop
git clone ССЫЛКА_ИЗ_ПУНКТА_1
```

**Отправка решения (для каждого ДЗ):**

```bash
cd ~/Desktop/css-seminar-ваша_фамилия

# 1. Обновите main и создайте ветку для ДЗ (вместо 1 - номер задания)
git checkout main
git pull
git checkout -b hw-1

# 2. Положите файлы решения в папку homework-1, затем:
git add homework-1
git commit -m "ДЗ 1"
git push -u origin hw-1
```

3. Откройте репозиторий на GitHub. Появится желтая плашка **Compare & pull request** - нажмите её, затем **Create pull request**.
   Проверьте, что в шапке указано `base: main ← compare: hw-1`.

> **Важно:** каждое новое ДЗ начинайте с команд `git checkout main` и `git pull` и создавайте **новую** ветку (`hw-2`, `hw-3`...). Иначе в новую сдачу попадут файлы прошлых заданий.

---

### Как получить проверку

Когда мы проверим работу, вам придет письмо. Откройте свой Pull Request (вкладка **Pull requests** в репозитории):

- вкладка **Conversation** – общий комментарий к работе;
- вкладка **Files changed** – комментарии к конкретным строкам.

Статус работы:

| Что вы видите | Что это значит |
|---|---|
| **Approved** | Работа принята |
| **Merged** (фиолетовая метка) | Работа принята и закрыта, ничего делать не нужно |

## Настройка SSH-ключа (только для способа Б)

Ключ нужен, чтобы отправлять решения из терминала. Если сдаете через сайт, этот раздел можно пропустить.

1. Создайте ключ (вместо почты – ваша почта от GitHub):

```bash
ssh-keygen -t ed25519 -C "ваша_почта@example.com"
```

На все вопросы нажимайте **Enter**.

2. Выведите публичный ключ:

```bash
cat ~/.ssh/id_ed25519.pub
```

3. Скопируйте всю строку целиком – она начинается с `ssh-ed25519`.
4. На GitHub: аватар справа вверху → **Settings** → **SSH and GPG keys** → **New SSH key**. В поле **Title** напишите любое название (например, «Мой ноутбук»), в поле **Key** вставьте ключ → **Add SSH key**.
5. Проверьте подключение:

```bash
ssh -T git@github.com
```

На вопрос `Are you sure you want to continue connecting?` ответьте `yes`. Если появилось `Hi <ваш ник>! You've successfully authenticated` – все работает
